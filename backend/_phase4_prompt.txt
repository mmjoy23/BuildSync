Example:

{
  "leaseId": "...",

      "type": "RENT",
      "description": "Monthly Rent",
      "amount": "25000.00"
    },
    {
      "type": "ELECTRICITY",
      "description": "Electricity",
      "amount": "3200.00"
    },
    {
      "type": "WATER",
      "description": "Water",
      "amount": "800.00"
    },
    {
      "type": "GAS",
      "description": "Gas",
      "amount": "1080.00"
    },
    {
      "type": "SERVICE_CHARGE",
      "description": "Service Charge",
      "amount": "2000.00"
    },
    {
      "type": "PARKING",

Use the actual Prisma field names from the existing schema.

IMPORTANT:

Backend must:

2. Calculate total from BillItems.

For the example above:

25000
+ 3200
+ 800
+ 1080
+ 2000
+ 1500
= 33580

Bill.totalAmount must become:

5. BILLING MONTH
==================================================

Use the existing Bill.billingMonth field.

The existing unique constraint:

must be respected.

If duplicate bill is attempted:
- return a safe 409 Conflict response.

Do not create duplicate monthly bills.

==================================================
6. BILL TOTAL
==================================================

Backend must be the authoritative source for Bill.totalAmount.

When creating a bill:

totalAmount =
SUM(all BillItem.amount)

Use Prisma Decimal or equivalent Decimal-safe arithmetic.

Never do:

Number(amount)

for financial calculations.

Do not trust:

req.body.totalAmount

If the request contains totalAmount:
- ignore it, or
- reject it as an unsupported field.

Prefer rejecting unexpected financial fields through validation.

==================================================
10. PAYMENT AMOUNT VALIDATION
==================================================

Payment amount must be:

> 0

and must not exceed the bill's remaining unpaid amount.

Calculate:

remaining =
bill.totalAmount - SUM(verified payments)

If:

payment.amount > remaining

reject with:

HTTP 400 or 409

Do not silently create overpayments.

Partial payments MUST be supported.

Example:

Bill total:
33580

Payment 1:
10000

Remaining:
23580

Payment 2:
5000

Remaining:
18580

This is valid.

==================================================
11. PAYMENT STATUS
==================================================

Use the existing PaymentStatus enum:

PENDING
VERIFIED
FAILED

Only VERIFIED payments count toward the bill's paid amount.

PENDING payments do not reduce the bill balance.

FAILED payments do not reduce the bill balance.

==================================================
12. PAYMENT VERIFICATION
==================================================

Because there is no real payment gateway yet, implement a controlled internal verification mechanism.

Suggested:

PATCH /api/payments/:id/verify

Allowed:
- ADMIN
- OWNER only if appropriate according to the existing architecture

Do NOT allow a normal TENANT to mark their own payment VERIFIED.

When verified:

1. Confirm payment exists.
2. Confirm it is currently PENDING.
3. Confirm amount is still valid against remaining bill balance.
4. Set Payment.status = VERIFIED.
5. Set verification date if the existing model supports it.
6. Generate/store receipt number.
7. Recalculate bill payment state.

Do this transactionally where appropriate.

If an admin verifies a payment, it should become a genuine internal verified record.

==================================================
13. RECEIPT NUMBER
==================================================

When a payment becomes VERIFIED:

Generate a unique receipt number.

Example format:

BS-2026-000001

Use the existing Payment.receiptNumber field.

Requirements:
- unique
- deterministic enough for testing
- collision-safe

Do not use the database ID directly as a public receipt number.

==================================================
14. BILL PAYMENT STATUS
==================================================

Use the existing BillStatus enum:

PENDING
PAID
OVERDUE

Important:

BillStatus should reflect verified payments and due date.

Calculate:

paidAmount =
SUM(Payment.amount WHERE status = VERIFIED)

remainingAmount =
totalAmount - paidAmount

Rules:

If remainingAmount <= 0:
    Bill.status = PAID

Else if current date > dueDate:
    Bill.status = OVERDUE

Else:
    Bill.status = PENDING

Do not create a new status enum.

Do not automatically create late fees.
